# `strings` 练习知识点

> 对应 rustlings `exercises/strings/` 的 4 道题
> 示例均在 rustc 1.98.1 上实际编译运行验证

## 总览

| 题目 | 考察点 | 一句话 |
|------|--------|--------|
| `strings1.rs` | 返回值类型：`&str` → `String` | 函数要 `String`，字面值是 `&str`，必须显式转换 |
| `strings2.rs` | `&String` → `&str` 自动转换 | 参数写 `&str` 更通用，`&word` 就能传 |
| `strings3.rs` | `trim` / `replace` / `format!` | 分清哪些方法返回 `&str`、哪些返回 `String` |
| `strings4.rs` | 类型识别 | 拿到一个值，判断它是 `String` 还是 `&str` |

---

## 1. `strings1.rs` —— 返回 `String` 而不是 `&str`

```rust
fn current_favorite_color() -> String {
    "blue".to_string()
}
```

**问题所在：** `"blue"` 的类型是 `&'static str`（字符串字面值），而函数签名要求返回 `String`，直接 `return "blue";` 会报：

```
error[E0308]: mismatched types
  expected `String`, found `&str`
```

**五种等价写法**（都会在堆上分配并拷贝内容）：

| 写法 | 走的 trait | 备注 |
|------|-----------|------|
| `String::from("blue")` | — | 最惯用，语义清晰 |
| `"blue".to_string()` | `ToString` | 任何实现 `Display` 的类型都有 |
| `"blue".to_owned()` | `ToOwned` | 语义是"把借用变成拥有" |
| `"blue".into()` | `Into` | 需要上下文能推断出目标类型 |
| `format!("{}", "blue")` | — | 格式化宏，返回 `String` |

**为什么字面值是 `&str`？** 字面值编译期就被写进可执行文件的只读数据段，整个运行期都存在（`'static` 生命周期），不需要堆分配，所以它只是个借用：

```rust
fn f() -> &str {
    "blue"          // ✅ 'static，可以直接返回
}

// fn g() -> &str {
//     let s = String::from("blue");
//     &s          // ❌ 悬空引用：s 在函数结束时已被释放
// }
```

## 2. `strings2.rs` —— `&String` 自动变 `&str`

```rust
fn is_a_color_word(attempt: &str) -> bool {
    attempt == "green" || attempt == "blue" || attempt == "red"
}

let word = String::from("green");
is_a_color_word(&word);          // ✅
```

`&word` 的类型是 `&String`，但函数要 `&str`——能编译是因为 **解引用强制转换（deref coercion）**：`String` 实现了 `Deref<Target = str>`，所以 `&String` 会自动解引用成 `&str`。

三种传参方式都合法：

```rust
is_a_color_word(&word);          // &String → &str（自动）
is_a_color_word(word.as_str());  // 显式转换
is_a_color_word("green");        // 字面值本来就是 &str
// is_a_color_word(word);        // ❌ expected `&str`, found `String`
```

**函数参数为什么写 `&str`：**

| 参数类型 | 能接受的实参 |
|---------|-------------|
| `&str` | `&String`（自动转）、`&str`、字面值、切片 |
| `&String` | 只有 `&String` |

> 同理，`&[T]` 比 `&Vec<T>` 通用。

## 3. `strings3.rs` —— `trim` / `replace` / `format!`

```rust
fn trim_me(input: &str) -> String {
    input.trim().to_string()          // trim 返回 &str，需要转成 String
}

fn compose_me(input: &str) -> String {
    format!("{} world!", input)       // 也可以用 input.to_string() + " world!"
}

fn replace_me(input: &str) -> String {
    input.replace("cars", "balloons") // replace 已经返回 String，不用再 to_string()
}
```

**关键：分清方法的返回类型**

| 返回 `&str`（借用原串的一部分） | 返回 `String`（新分配一块内存） |
|---|---|
| `trim()` / `trim_start()` / `trim_end()` | `replace()` |
| `&s[0..n]`（切片） | `to_string()` / `to_owned()` |
| `&s` / `s.as_str()` | `to_lowercase()` / `to_uppercase()` |
| `split(..).next()` 之类 | `format!()` |

**判断依据：结果是否已经存在于原串里？**

- `trim` 只是把首尾边界往里挪一挪 —— 结果本来就是原串的一部分 → 可以借用，返回 `&str`
- `to_lowercase` 的结果长度**可能变化**（`'İ'` 小写后是 `"i̇"`，2 个字符），原串里没有这块数据 → 必须新分配，返回 `String`

**不要手写 `trim`。** 下面这个"自己实现"的版本有三个坑（实测会在第三种情况 panic）：

```rust
let mut start = 0;
let mut end = input.len();
while start < end && input.as_bytes()[start] == b' ' {
    start += 1;
}
while input.as_bytes()[end - 1] == b' ' {   // ⚠️ end 可能减到 0 后下溢
    end -= 1;
}
input[start..end].to_string()
```

| 坑 | 说明 |
|----|------|
| ① 整数下溢 | 输入全是空格时 `end` 会减到 0，`end - 1` 在 debug 模式下 panic：`attempt to subtract with overflow` |
| ② 判断范围太窄 | 只认 `b' '`，处理不了 `\t`、`\n`、全角空格；标准库 `trim()` 按 `char::is_whitespace()` 判断 |
| ③ 多字节不安全 | 按字节下标切片对中文/emoji 可能切在字符中间 → panic |

**其他常用方法：**

```rust
let s = "  Hello World  ";

let t: &str   = s.trim();                     // [Hello World]（借用）
let r: String = s.replace("World", "Rust");   // [  Hello Rust  ]（新分配）
let u: String = s.trim().to_lowercase();      // [hello world]
let n: i32    = "  42  ".trim().parse().unwrap();  // 42
```

| 方法 | 返回 | 说明 |
|------|------|------|
| `contains(pat)` / `starts_with` / `ends_with` | `bool` | 子串 / 前后缀判断 |
| `find(pat)` | `Option<usize>` | 子串起始的**字节**下标 |
| `split(pat)` | 迭代器 | 惰性切分，需要时 `.collect()` |
| `len()` | `usize` | **字节数**，`"中".len() == 3` |
| `push_str(&str)` / `push(char)` | `()` | 原地追加（变量须为 `mut`） |

## 4. `strings4.rs` —— 判断每个值的类型

| 表达式 | 类型 | 原因 |
|--------|------|------|
| `"blue"` | `&str` | 字符串字面值 |
| `"red".to_string()` | `String` | `ToString` trait |
| `String::from("hi")` | `String` | 关联函数 |
| `"rust is fun!".to_owned()` | `String` | `ToOwned` trait，等价于 `to_string()` |
| `"nice weather".into()` | 由上下文推断 | 这里参数类型是 `String`，所以推断为 `String` |
| `format!("Interpolation {}", "Station")` | `String` | 格式化宏总是返回新 `String` |
| `&String::from("abc")[0..1]` | `&str` | 对 `String` 切片得到切片 |
| `"  hello there ".trim()` | `&str` | 借用原串的一部分 |
| `"Happy Monday!".to_string().replace("Mon", "Tues")` | `String` | `replace` 返回新 `String` |
| `"mY sHiFt KeY iS sTiCkY".to_lowercase()` | `String` | 大小写转换可能改变长度，必须新分配 |

**记忆窍门：**

- 带 `to_` / `into` / `from` / `format!` 的 → 生成**新的 `String`**（堆分配）
- 带 `trim` / `as_` / 切片 `[..]` 的 → 得到**借用的 `&str`**
- 字面值 `"..."` → 永远是 `&'static str`

---

## 易错点总结

1. **`"..."` 是 `&str`，不是 `String`** —— 返回类型是 `String` 时必须转换。
2. **`&String` 会自动变 `&str`**，所以 `is_a_word(&word)` 能编译；但 `is_a_word(word)`（不取引用）不行。
3. **`trim()` 返回 `&str`**，函数返回 `String` 时要 `.to_string()`。
4. **`replace()` 返回 `String`**，再 `.to_string()` 是多余的一次分配。
5. **`to_lowercase()` 返回 `String`**（可能变长），而 `trim()` 返回 `&str` —— 别记混。
6. **`&str` 的方法都不修改原串**，都是返回新值。
